Deploying on your Azure — one image, config-only

The Railway sandbox and your Azure production run the same container image built from this repo. Azure is turned on entirely by environment variables — no fork, no code branch. The adapters for Azure OpenAI, OIDC, an HTTP wallet gateway, Postgres, Redis and Application Insights are already in the codebase. Deployment is provisioning + wiring, not a rewrite.

Same image Config-only switch Already Azure-aware

01 The principle

One image, promoted by config. Nothing is Railway-specific and nothing is Azure-specific in the code — the same build runs in both places, and each mode adapter is chosen by an env var at boot. Verify any deployment at GET /api/health → it returns { authMode, modelMode, walletMode, mockRailsAllowed, database, storeBackend, redisConfigured, oidcIssuer }, so you can confirm prod is wired correctly without reading a log.

05 Deployment flow

  • Build & push — az acr build -r <acr> -t miai-web:<sha> . (repo Dockerfile, health at /api/health)
  • Provision the §2 resources; create the two Azure OpenAI deployments; load all secrets into Key Vault
  • Create the Container App with the image + §4 env (secrets as Key Vault refs). Target port 3000 (or PORT)
  • Migrations run automatically on first boot when DATABASE_URL is set — no separate step
  • Register webhooks against the prod host: Telegram setWebhook?url=…/api/consumer/telegram/webhook&secret_token=$TELEGRAM_BOT_SECRET
  • Verify GET /api/health → expect authMode:oidc · modelMode:azure · walletMode:http · database:postgres · mockRailsAllowed:false

06 Multi-tenant & open decisions

White-label model

Per-tenant, not per-fork: workspaceId = brand = tenant, and every consumer call is scoped to it — so each partner gets isolated memory, wallet and connectors off the one deployment. Registry: apps/web/src/lib/tenant-brands.ts. The sandbox is pinned to a single brand for a clean demo; the multi-tenant capability is intact.

Decisions still open — config, not code
  • Model path: Azure OpenAI direct vs their gateway
  • Identity: their OIDC issuer vs Google
  • Whose Azure subscription hosts it; tenant→partner map
  • Regions / residency: Postgres + Azure OpenAI co-located per market

None of these require code changes — they select which env values go in §4.
