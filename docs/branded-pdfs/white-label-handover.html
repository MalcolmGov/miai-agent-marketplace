Persistence & Storage Architecture

The platform includes fail-closed storage adapters configured in apps/web/src/lib/persistence/:

  • PostgreSQL Adapter: Primary persistent relational store with connection pooling and SSL verification.
  • Redis Session Adapter: Fast key-value lookups for active chat turns and token deductions.
  • File Fallback Guard: Blocked in production unless dual escape hatches are set, preventing accidental state loss.

4. Document & Knowledge Base Processing Engine

Enterprise Parsing Pipeline (apps/web/src/lib/ingest.ts)

Customers upload business guidelines, pricing sheets, and policy PDFs to customize their licensed agents. The ingestion engine has been hardened against corrupted binary payloads:

  • Mozilla PDF.js Engine: Employs pdf-parse built on pdfjs-dist, eliminating character corruption and raw stream dumps.
  • Multi-Column Layout Awareness: Reconstructs multi-line tables, line items, and invoice headers cleanly into markdown.
  • Sanitization & Chunking: Strips binary headers and control characters before passing context to LLM inference windows.
  • Supported Formats: PDF (.pdf), Plain Text (.txt), Markdown (.md), and direct clipboard text paste.

5. First-Party Rails Integration (OIDC, Wallet & Payment)

Because this is a white-labeled product under the MyInstantAI umbrella, the platform is engineered to wire directly into MyInstantAI’s existing core authentication, wallet, and billing systems without requiring code refactoring.

A. Single Sign-On & Corporate OIDC (MIAI_AUTH_MODE=oidc)

When switched to OIDC, the platform delegates user identity entirely to MyInstantAI’s identity provider (Keycloak, Auth0, Google Workspace, or Azure Entra ID): 

# OIDC Configuration Blueprint in .env
MIAI_AUTH_MODE=oidc
OIDC_ISSUER=https://auth.myinstantai.com/realms/miai-prod
OIDC_CLIENT_ID=miai-agents-platform
OIDC_CLIENT_SECRET=sec_miai_prod_oidc_secret_here
OIDC_REDIRECT_URI=https://agents.myinstantai.digital/api/auth/callback

Token Verification: The callback validates RS256/ES256 signatures against the issuer's .well-known/openid-configuration JWKS endpoint, mapping the email to workspace roles (owner, operator, readonly).

B. Token Wallet API (MIAI_WALLET_MODE=http)

Agent inference and tool calls deduct tokens directly from the user's primary MyInstantAI wallet account: 

# Wallet HTTP Adapter Config
MIAI_WALLET_MODE=http
WALLET_API_URL=https://wallet-api.myinstantai.internal
WALLET_SERVICE_TOKEN=sec_wallet_service_bearer_token
  • Pre-Inference Check: GET /balance verifies sufficient funds before executing LLM turns.
  • Post-Turn Deduction: Atomically posts prompt + completion token usage with transaction IDs.

C. Payment Gateway & Top-Ups

Users top up token packages directly inside the Agent Studio via MyInstantAI's billing gateway or webhooks: 

# First-Party Billing & Webhook HMAC
BILLING_WEBHOOK_URL=https://billing.myinstantai.internal/webhook
WEBHOOK_HMAC_SECRET=sec_hmac_sha256_webhook_signing
  • HMAC Signed Webhooks: Rejects unsigned or tampered payment callbacks.
  • Direct Credit: Top-ups immediately update the user's available token balance in the UI.

7. Enterprise Security Hardening & Fail-Closed Guardrails

The platform is engineered to comply with enterprise procurement and security diligence audits. Safety guardrails execute in real-time before prompts reach model context windows.

4 Live Pre-Prompt Guardrails

  • PCI-DSS Credit Card Scrubbing: Primary Account Numbers (PAN) and CVVs are masked with [REDACTED_CARD] before persistence or inference.
  • Prompt Injection & Jailbreak Refusal: System prompt exfiltration attacks and override attempts trigger immediate polite refusal.
  • Cross-Tenant Data Isolation: Strict workspace boundary checks prevent agent leakage between different MyInstantAI accounts.
  • Emergency / 911 Escalation: High-risk medical or suicide indicators immediately trigger human escalation paths.

Cryptographic Protection

  • PBKDF2 Password Hashing: 32-byte deterministic salt with 100,000 iterations for local credentials.
  • Embed Key Hashing: Public keys use SHA-256 HMAC tokens with domain origin restriction.
  • Subresource Integrity (SRI): The agent.js widget carries sha384 SRI hashes preventing CDN tampering.
  • Fail-Closed Boot Guard: Application halts at startup if secrets are defaults or shorter than 16 characters.
